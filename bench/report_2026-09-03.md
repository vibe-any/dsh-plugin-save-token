# save-token 插件优化版 A/B 验证报告（2026-09-03，round 2）

> 对象：dsh-plugin-save-token **v2.4.1**（2026-08-29 报告后的优化版：P1 纯压缩模块重构、
> P2 无损 TOON 编码优先 + 门控回退、P3 cache-aware 层、P4 面板/回放 KPI 与 UI）。
> 方法：与 round-1 同一套 bench 数据集（GAIA×2、Terminal-Bench×2、SWE-bench-Verified×2）
> × {baseline, treatment} × n=2，唯一变量 = 插件 compress/dedupe(/compactAssist) 开关。
> 计量：DSH 原生 `tokenUsage` 四桶（无第三方估计）；本轮新增**缓存命中率**为一等指标。
> 运行宿主：Linux（round-1 为原生 macOS），判据与口径保持同源。

---

## TL;DR

6 任务 × 2 臂 × n=2，**24/24 集有效，成功率两臂均 100%（24/24），零无效集**：

- **成功率零损伤再次成立**（两轮合计 48/48 全成功）——这是两轮 A/B 中最稳健的结论。
- **总 Token：treatment 比 baseline 高 +38.0%**（6,669,489 vs 4,832,174）。但该差额被
  **单个离群集主导**：tb-access-logs treatment r1 的 agent 选择了「反复全量打印日志」
  策略（18 步、48 次 marker 回放），单集 1,864,562 tok，占 treatment 臂总量的 28%。
  **剔除这一个集后，treatment = 4,804,927 vs baseline = 4,832,174（−0.6%，基本持平）**。
- **稳定省 Token 的任务**：swe-sympy **−19.7%**（两重复 −10.4%/−28.2% 同向）、
  swe-django **−18.0%**（−21.0%/−13.2% 同向）——长上下文 + 大测试输出场景。
- **缓存命中率（本轮一等指标）：treatment 90.7% vs baseline 90.0%（+0.7pp）**，
  两臂基本一致；最重的 dump 集在反复展开下仍保持 91.1% 命中率（uncached 仅占 8.9%），
  证明 v2.4.1 的 cache-aware marker 回放层在高压场景下**守住了缓存**而非提升缓存。
- **压缩触发 11 次，覆盖 6/12 个 treatment 集**，avoided 估计合计 560,442
  （占触发集 Token 的 13.8%）；无损 TOON 编码触发 0 次（本负载未命中其触发面）。

**给使用者的判据（两轮合并后修正）**：插件的单输出压缩机制有效且零成功率代价，
但 **n=2 下 agent 策略方差可达 ±3~15 倍，远大于压缩收益本身**；聚合 Δ 由策略方差
主导（round-1 的 −17.6% 与本轮的 +38.0% 都是同一噪声的两面）。可靠信号是：
① 成功率不受损；② 长上下文 SWE 型任务两轮平均有小幅净收益；
③ 缓存命中率不受插件影响（±1pp 内）。

## 方法

- **任务集**（6 任务锁定，同 round-1）：
  - GAIA L2 `54612da3`（locomotives，xlsx 附件，金标 60）
  - GAIA L2 `c61d22de`（arxiv-regulation，多跳 web，金标 egalitarian）
  - Terminal-Bench `analyze-access-logs`（300KB 日志直出）
  - Terminal-Bench `jsonl-aggregator`（5×200k 记录聚合）
  - SWE-bench-Verified `sympy__sympy-24562`（base `b1cb676`）
  - SWE-bench-Verified `django__django-16595`（base `f9fe062`）
- **臂**：baseline = compress/dedupe/compactAssist 全关；treatment = 全开。
  expand 工具两臂恒注册（对称）。每格 n=2，**完全串行**，每集发射前
  POST /reset（清仪表与去重缓存）。
- **行为条件**：两臂对称施加与 round-1 相同的 HARD CONSTRAINTS
  （禁文件重定向、禁 read 批量查看、测试输出必须可见），保持「大输出直出」区间。
- **计量**：每集独立会话（projcache 键 = subagent id，发射时验证），
  四桶真值 + 本轮新增缓存命中率（ΣcacheRead / Σ输入三桶）；
  插件侧 ce/dedupe/lossless/replays/avoided 作为触发面旁证。
- **缓存命中率口径（本轮新增）**：按臂聚合 = ΣcacheRead / Σ(uncachedInput+cacheRead+cacheWrite)，
  与 DSH 原生计费一致；单集命中率另列。v2.4.1 的 cache-aware 层（P3）以「提高缓存命中、
  降低 uncached 重放」为优化假设之一，本指标直接检验该假设。

## 判据与校准（本轮实测）

- TB 两题：官方测试脚本红/绿双向 oracle **4/4 通过**（修复：校验脚本补 .gz 解压回退）。
- django：阴性对照 success=0，金解 success=1（F2P `test_alter_alter_field` + P2P
  `migrations.test_optimizer` 全过）。
- sympy：阴性对照 success=0，金解 success=1（F2P `test_issue_24543` + P2P
  test_numbers/test_priority/test_subs 三文件）。
- GAIA：归一化答案比对（`scripts/judge_gaia.py`，gold 来自 manifest）。

### 跨宿主可移植性修正（相对 round-1，两臂对称、不影响 A/B 差分）

1. **sympy P2P 清单**：round-1 的 `sympy-24562.p2p_files.json` 含 macOS 绝对路径
   （/Users/samueli/...）；本轮改为仓库相对路径（同一组 3 个测试文件，判定语义不变）。
2. **sympy P2P 漂移节点**：本宿主 CPython 下 `Float('_1')` 不再抛 ValueError，
   `test_numbers.py::test_Float` 在**任何正确修复的树上都失败**（金解树实测）；
   判定改用 pytest 节点选择，P2P 扫描 deselect 该单节点（其余 180+ 测试保留）。
   F2P 精确节点不变。两臂同判。
3. **patch 工具**：宿主无 apt/patch，本地构建 GNU patch 2.7.6 至 ~/.local/bin
   （judge 脚本零改动）。
4. **sympy episode venv 增加 pytest**（judge 依赖，uv 缓存秒级，不影响 agent 行为）。

## 协议增量（v2.4.1 相关）

- **去重 TTL 600s（原 90s）不再强制集间长等待**：v2.4.1 的 `POST /reset` 会清空整个
  去重缓存（src/index.js `resetAll()`），且去重指纹含 sessionId + 参数 + 字节
  （src/compress.js `dedupeFingerprint`）——前集完全落定后 reset 再发射，跨集污染在
  结构上不成立。串行纪律保留（每集落定 → 收集 → reset → 下一集）。
- **collect_episode.py 插件快照字段扩展**（附加式，旧字段不变）：
  dedupeSavedBytes / losslessEncodes / tabularWindows / replays / auxRequests /
  estPromptTokens / cacheHitPct / reliefPct / estRatio。
- **analyze2.py**（新增）：逐任务/总体表带命中率列；全部 12 对同序配对（round-1 只配
  对触发集）；跨轮对比表（round-1 vs 本轮）。

### 缓存命中率（本轮新增口径）

- **按臂聚合：baseline 90.0% vs treatment 90.7%** —— 插件对缓存命中整体中性（+0.7pp）。
- 分层看：压缩触发集命中率 90.6%，未触发集 90.8%，baseline 90.0% —— 三者几乎重合。
- 最重压场景（tb-access-logs r1，1.86M tok，48 次 marker 回放）仍保持 **91.1%** 命中率，
  uncached 输入仅 8.9% —— cache-aware 回放层把「压缩桩跨请求重注入」做成了缓存友好的
  稳定前缀，避免了无压缩时可能出现的 uncached 放大。
- SWE 长上下文任务两臂都在 92–95.6% 区间，插件未改变其缓存行为。
- 跨轮对比：round-1 baseline 86.9% / treatment 91.2%；本轮 90.0% / 90.7% ——
  两轮、两臂全部落在 87–91% 窄带内，**缓存命中率是该插件影响最小的指标**。

### 触发分层（treatment 臂内）

- 触发集（ce>0）：n=6，总 4,057,375 tok，avoided 560,442（占其 13.8%），命中率 90.6%
- 未触发集（ce=0）：n=6，总 2,612,114 tok，命中率 90.8%
- 无损 TOON 编码：**0 次触发**（本组负载无满足其触发面的输出形态——与实现侧确认的
  触发条件一致，非缺陷）；去重命中：0 次（串行 + 每集 reset 清指纹，符合预期）。

以及缓存命中不受影响。

## 局限

- n=2 无显著性检验；**单集策略方差可达 ±3~15 倍**（本轮 tb-access-logs r1 的 1.86M
  离群、gaia-locomotives r2 的联网核对），聚合 Δ 必须配对并剔离群解读（两臂对称）。
- avoidedTokens 为插件回放估计（旁证）；净节省以同格配对 Token 差额为准。
- 行为约束是实验条件（两臂对称），测量的是「直出型工作负载下的插件价值」。
- GAIA 题存在公开基准污染（本轮 treatment r2 明确检索到了答案键），两臂对称暴露。
- 本轮宿主为 Linux（round-1 为 macOS），跨轮对比含宿主差异；同轮内两臂完全同宿主。
- sympy 判定器为可移植性改为 pytest 节点选择（deselect 环境漂移节点 test_Float，
  该节点在任何正确修复的树上都失败，金解树实测），两臂同判；可能间接影响 agent 的
  验证输出形态（round-1 用 bin/test 全量输出，本轮 agent 普遍用 pytest 摘要），
  这是 sympy 任务 ce=0 的部分成因。
- captain 会话与 episode 共享插件仪表，reset 后窗口内的仪表快照含 captain 流量
  （projcache 四桶按会话隔离，为统计口径，不受影响）。
- 处置记录：1 次 launch 弃档（gaia-arxiv treatment r1 提示词笔误，未计入，
  原样重发）；无重试触顶（每格重试 0/2）。
